# Use grab Session Mode

I will provide repository context strictly through `grab` commands. You must treat the accumulated `grab` context as the **only source of truth**.

## Core Rules

* Never assume code outside provided `grab` output.
* When context is missing, ask for a **batch of exact `grab` commands**.
* Always request commands in **copy-pasteable batches**.
* Prefer `grab --functions .` first so you can work from exact function coordinates.
* Use `grab --tree` when file or directory layout is unclear.
* Prefer exact line-range extraction when function coordinates are known.
* Prefer multiple small, precise extractions over huge files.
* Do not remove existing logic unless explicitly asked.
* Preserve existing behavior, then add compatibility or fallback logic.
* When changing code, show **BEFORE** and **AFTER**.
* Prefer **full function** or **full section replacements** over tiny fragments.

---

## Standard Context Acquisition Workflow

When repository context is required, request commands in this order:

```bash
grab --clear
grab --tree
grab --functions .
```

Then request targeted extractions:

```bash
grab 120 180 path/to/file.cs FunctionOrSectionName
grab 240 310 path/to/file.cs AnotherFunctionName
grab "ExactPattern" .
```

---

## Command Selection Rules

Use this order whenever possible.

### 1. Start fresh

```bash
grab --clear
```

### 2. Capture repository structure (if needed)

```bash
grab --tree
```

### 3. Index functions/tasks

```bash
grab --functions .
```

### 4. Extract exact implementations

Use coordinates obtained from the function index:

```bash
grab START END FILE LABEL
```

Examples:

```bash
grab 312 383 NotificationDispatcher.cs ProcessNotificationDelivery
grab 448 486 NotificationDispatcher.cs ShouldRetryNotification
```

### 5. Search exact symbols, strings, settings, or error messages

```bash
grab "EXACT_PATTERN" .
```

Examples:

```bash
grab "duplicate notification" .
grab NotificationRetryLimit .
grab DeliveryDeduplicationWindowMinutes .
```

## Context Acquisition Principles

* Treat the accumulated `grab` session as the only available repository context.
* Never rely on memory from previous repositories.
* Never infer the existence of functions, fields, classes, or configuration that have not been extracted.
* Request additional context whenever uncertainty exists.
* Prefer deterministic extraction over guessing.

4. AFTER code block


## Replace

```text
FunctionName
```

## BEFORE

```csharp

```

## AFTER

